# 需求概述 — 错误处理日志与覆盖层优化

> **项目**: vext
> **创建日期**: 2026-04-12
> **状态**: CP1 已确认（2026-04-12）

## 一、背景

当前 vext 框架的错误处理机制存在两个影响开发效率的问题：

### 问题 A：服务端错误无控制台日志

`createErrorHandler`（`error-handler.ts`）负责捕获所有中间件链错误并格式化响应。
其注释明确写道"日志由调用方 adapter 的 try-catch 或上层中间件负责"，
但实际上 adapter 层和 access-log 中间件只输出了一行状态码：

```
POST /api/users 500 12ms | 127.0.0.1
```

未知 500 错误的 **错误类型、message、stack trace 完全不出现在控制台**，
开发者必须通过响应体（或开发者工具）才能定位错误根因。

### 问题 B：Dev 模式 HTML 错误覆盖层（范围外，预留）

Dev 模式注入了 `devOverlay`，当请求的 `Accept` 头包含 `text/html` 时返回 HTML 错误页。
该能力本质上属于**前端页面渲染**场景（SSR/页面路由出错时在浏览器展示友好错误页）。

**设计决策**：vext 当前为纯 API 框架，尚未实现前端页面渲染能力：
- API 客户端（curl/Postman/axios）的 Accept 不含 `text/html`，overlay 不触发，**不受影响**
- 用浏览器直接访问 API 属于边缘调试场景，影响有限
- 因此本次不扩展 overlay（不新增 `skipPaths` 等配置），作为预留能力，待 SSR 落地时再完整接入

## 二、需求列表

| # | 需求 | 优先级 | 说明 |
|---|------|:------:|------|
| R1 | `createErrorHandler` 接受可选的 `logger` 参数，未知 500 错误记录 `error` 级别日志（含 stack trace） | 🔴 P0 | 核心问题修复 |
| R2 | HttpError 5xx 同样记录 `error` 日志（默认开启） | 🟡 P1 | 5xx 是服务端责任，也需可见 |
| R3 | 新增 `response.logErrors` 配置项，控制 4xx 错误是否记录 `warn` 日志（默认关闭） | 🟡 P1 | 高流量场景避免日志噪音 |
| R4 | `bootstrap.ts` 和 `dev-bootstrap.ts` 创建 errorHandler 时传入 `app.logger` | 🔴 P0 | R1 的配套改动 |

> **说明**：Dev 模式 HTML 错误覆盖层（devOverlay）不在本次范围内，作为预留能力待 SSR 场景落地后接入。

## 三、不在范围内

- 不修改 access-log 中间件的日志格式
- 不改变 `hideInternalErrors` 的现有语义（控制响应体是否含 stack）
- 不涉及 VextValidationError 的日志（参数校验失败属于调用方问题，不记录）
- 不新增依赖

## 四、涉及文件

| 文件 | 变更类型 |
|------|---------|
| `src/lib/middlewares/error-handler.ts` | 修改（增加 logger 参数和日志逻辑） |
| `src/types/app.ts` | 修改（`VextResponseConfig` 新增 `logErrors` 字段） |
| `src/lib/bootstrap.ts` | 修改（创建 errorHandler 时传入 logger） |
| `src/lib/dev/dev-bootstrap.ts` | 修改（创建 errorHandler 时传入 logger） |
| `test/unit/error-handler.test.ts` | 新建（补充 logger 注入和 logErrors 配置测试） |

## 五、验收标准

1. 未知 500 错误发生时，控制台能看到 `error` 级别日志，包含错误 message 和 stack trace
2. HttpError 5xx 出现时，控制台能看到 `error` 级别日志，包含 status 和 message
3. `response.logErrors.http4xx = true` 时，4xx 错误在控制台输出 `warn` 日志
4. 所有改动向后兼容（不传 logger 时与现有行为完全一致）
5. 新增单元测试覆盖 logger 注入路径
