## 如何理解规则等级

| 等级       | 含义                                                             |
| ---------- | ---------------------------------------------------------------- |
| `MUST`     | 为满足所述框架合同，必须遵守的条件                               |
| `MUST NOT` | 与所述合同或职责边界冲突的行为，不能采用                         |
| `SHOULD`   | 通常适用的建议；项目有明确原因时可以选择其他做法，并验证相应边界 |
| `MAY`      | 可选行为，按页面给出的适用条件选择                               |

规则先有适用条件，再判断等级。例如启用数据库的规则不要求每个应用都必须使用数据库；资源关闭建议也不代表框架能够自动取消所有外部副作用。

有些限制由运行时直接拒绝，有些职责边界需要项目设计和测试保证。以规则正文中的实现说明为准，不能把所有 `MUST` 都理解成已有自动静态检查器。

## 引用一条规则

规则使用稳定 ID，例如 [VEXT-CONTRACT-001](/zh/specification/validation-and-contracts#vext-contract-001)。引用时同时保留文档语言、规则 ID 和具体页面链接；不要只复制一段脱离条件的标题。

同一规则的不同语言版本共享 Rule ID。规则正文或实现版本发生变化时，应重新核对完整上下文，避免把旧快照的说明用于新的代码。

## 文档的分工

| 文档角色        | 应承载的内容                           |
| --------------- | -------------------------------------- |
| Specification   | 职责、合同、约束与规则等级             |
| Guide           | 前置条件、操作步骤、使用方式和常见问题 |
| Reference       | 精确类型、字段、默认值、生命周期与错误 |
| Example         | 可运行的组合用法与验证步骤             |
| Troubleshooting | 症状、排查依据、原因、修复与复验       |
| Resource        | 入口、索引及其他参考资料               |

规则页链接到操作与参考页面，避免把每条规范扩写成重复教程。一个主题可以有多种角色的页面，角色相同也不要求全部页面使用同一章节模板。

## 工具引用边界

文档清单使用 `docId` 表达逻辑身份，具体语言记录由 `(docId, locale)` 区分。Rule ID 在 `spec-rules.json` 中的字段名是 `id`，规则记录由 `(id, locale)` 区分；例如 `id: "VEXT-CONTRACT-001"`。工具应使用生成产物中的实际 URL 与当前文档快照，不应根据目录名猜测另一种语言的链接。

这些标识用于引用文档和规则，不代表已经实现能力图谱或代码合规检查。更多机器索引说明见[文档数据与 AI](/zh/resources/documentation-data-and-ai)。
