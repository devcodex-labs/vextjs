# v0.1.0 - 初始版本（Phase 0 ~ Phase 3）

**发布日期**: 2026-03-04
**版本类型**: Pre-release
**重要性**: ⭐⭐⭐⭐⭐ — 首次发布，覆盖 Phase 0 ~ Phase 3 全部功能

---

## 🎯 核心主题

vextjs 首个预发布版本，从零实现一个完整的 Node.js Web 框架：

- **Phase 0**：骨架验证（核心类型 + 最小可运行框架）
- **Phase 1**：MVP（全部核心模块：配置、日志、中间件、服务、插件、路由、i18n）
- **Phase 2A**：开发体验基础（`vext dev` Cold Restart + `vext build` + OpenAPI）
- **Phase 2B**：热重载（三层 Soft Reload：Tier 1/2 软重载 + Tier 3 冷重启）
- **Phase 3**：企业级（Cluster 多进程 + Multi-Adapter + MonSQLize 内置插件）

## ✅ 变更清单

### Phase 0：骨架验证

**目标**：最小可运行框架，验证核心接口设计。

#### 核心类型定义

新建 `src/types/` 目录，定义框架核心接口：

| 类型 | 说明 |
|------|------|
| `VextApp` | 应用实例接口（挂载 logger / services / fetch / throw 等） |
| `VextRequest` | 请求抽象（统一封装各 adapter 的原生请求对象） |
| `VextResponse` | 响应抽象（统一封装各 adapter 的原生响应对象） |
| `VextAdapter` | Adapter 接口（7 成员：registerRoute / registerNotFound / listen / close / buildHandler / getAdapterType / nativeApp） |
| `VextMiddleware` | 中间件签名（`(req, res, next) => Promise<void>`） |
| `HttpError` | 业务异常类（status / code / message / requestId） |

#### AsyncLocalStorage 请求上下文

新建 `src/lib/request-context.ts`：

- 基于 Node.js `AsyncLocalStorage` 实现请求级上下文存储
- `RequestContextStore` 存储 `requestId` 和 `locale`
- 每个请求独立隔离，解决并发请求全局变量竞态问题

#### createApp + Hono Adapter

- `src/lib/app.ts`：`createApp()` 工厂函数，初始化 `VextApp` 实例
- `src/adapters/hono/`：首个 adapter 实现，基于 Hono + @hono/node-server
  - `executeChain()`：洋葱模型中间件链执行器
  - `registerRoute()` / `registerNotFound()`：路由注册
  - `listen()` / `close()`：HTTP 服务器生命周期

#### 基础脚手架

- `src/lib/define-routes.ts`：`defineRoutes()` 路由声明辅助函数
- `src/cli/index.ts` + `src/cli/start.ts`：`vext start` 生产模式启动命令
- `src/lib/bootstrap.ts`：启动流程编排（8 步骤顺序执行）

### Phase 1：MVP v0.1.0

**目标**：完整可用的生产级框架核心。

#### 配置系统

`src/lib/config-loader.ts`：

- 三层配置合并：`default.ts` → `{NODE_ENV}.ts` → `local.ts`
- 环境变量覆盖（`VEXT_PORT` / `VEXT_HOST` 等）
- `deepMerge()` 深度合并（支持嵌套对象，保留 `middlewares` 独立合并）
- `validateConfig()` Fail Fast 校验（port / adapter / middlewares / rateLimit 等）
- `deepFreeze()` 配置对象只读锁定

#### 日志系统

`src/lib/logger.ts`：

- 基于 pino 的高性能结构化日志
- pino mixin 钩子：每条日志自动从 `requestContext` 读取并注入 `requestId`
- 支持 pretty（开发）/ JSON（生产）双模式
- `app.logger.child()` 创建带固定字段的子 logger

#### 内置中间件（6 个）

| 中间件 | 文件 | 说明 |
|--------|------|------|
| request-id | `src/lib/middlewares/request-id.ts` | UUID v4 生成/透传，写入 requestContext + 响应头 |
| cors | `src/lib/middlewares/cors.ts` | 可配置来源、方法、头，支持预检请求缓存 |
| body-parser | `src/lib/middlewares/body-parser.ts` | JSON + URL-encoded，可配置大小限制 |
| rate-limit | `src/lib/middlewares/rate-limit.ts` | 基于 flex-rate-limit，按 IP/用户/自定义 key 限流 |
| response-wrapper | `src/lib/middlewares/response-wrapper.ts` | 统一包装为 `{ code, data, message, requestId }` |
| error-handler | `src/lib/middlewares/error-handler.ts` | HttpError + 校验错误 + i18n 错误消息处理 |

#### 校验中间件

`src/lib/validate-middleware.ts`：

- 集成 schema-dsl，支持 `params` / `query` / `body` 三维度校验
- 通过 `src/lib/schema-adapter.ts` 防腐层解耦，future-proof 替换底层 DSL

#### 服务加载器

`src/lib/service-loader.ts`：

- 自动扫描 `src/services/` 目录
- 将服务实例注入 `app.services.<name>`
- 运行时循环依赖检测（DFS 拓扑排序）

#### 中间件加载器

`src/lib/middleware-loader.ts`：

- 扫描 `src/middlewares/`，注册命名中间件
- 支持路由级中间件白名单引用（`config.middlewares`）
- 按名称解析，路由注册时自动查找

#### 插件系统

`src/lib/plugin-loader.ts` + `src/lib/define-middleware.ts`：

- `definePlugin()` 工厂函数（声明式插件定义）
- 插件生命周期：`setup(app)` 在 bootstrap 阶段执行
- 插件可通过 `app.use()` 注册全局中间件（bootstrap 完成后锁定）
- 插件可通过 `app.extend()` 在 app 上挂载自定义方法/属性

#### 路由加载器

`src/lib/router-loader.ts`：

- 文件即路由：扫描 `src/routes/`，自动推断路径前缀
- 支持 `defineRoutes()` 声明式路由集合
- 集成 OpenAPI collector（可选）
- 路由级中间件链组装

#### i18n 加载器

`src/lib/i18n-loader.ts`：

- 自动扫描 locale 目录，加载翻译文件
- `app.throw()` 的 `I18nError.create()` 通过 `requestContext.locale` 自动翻译错误消息
- 支持 Accept-Language 解析

#### 内置 HTTP 客户端

`src/lib/fetch.ts`：

- 封装 Node.js 18+ 原生 `fetch`
- 自动从 `requestContext` 读取 `requestId` 并注入到出站请求头（分布式追踪）
- 超时控制（AbortController + setTimeout）
- 幂等方法自动重试（GET/HEAD/OPTIONS/PUT/DELETE）
- 结构化日志（method / url / status / duration / requestId）
- `create()` 工厂：创建预配置子客户端（固定 baseURL + 默认 headers）

#### 优雅关闭

`src/lib/shutdown.ts`：

- 监听 SIGTERM / SIGINT 信号
- 按顺序关闭：停止接受新请求 → 等待在途请求完成 → 执行 onClose 钩子 → 退出

**目标**：`vext dev`（Cold Restart）+ `vext build` + OpenAPI 文档。

#### DevCompiler（esbuild 开发编译器）

`src/lib/build/shared-esbuild-config.ts` + `src/lib/build/dev-compiler.ts`：

- 基于 esbuild 的快速 TypeScript 转译
- 增量编译（仅重新编译变更文件）
- 输出到 `.vext/dev/`，tsconfig paths 预解析缓存

#### FileWatcher（文件监听）

`src/lib/dev/file-watcher.ts` + `src/lib/dev/change-classifier.ts`：

- 基于 `fs.watch` 零依赖实现
- 支持 Docker 环境下的 polling 模式

#### ColdRestarter（冷重启）

`src/lib/dev/cold-restarter.ts` + `src/lib/dev/dev-bootstrap.ts`：

- 文件变更 → 终止子进程 → 重新编译 → 重启子进程
- `dev-bootstrap.ts`：将 bootstrap 拆分为「不可重载阶段」和「可重载阶段」，为 Phase 2B Soft Reload 奠基

#### vext build（生产构建）

`src/lib/build/build-compiler.ts` + `src/cli/build.ts`：

- 使用 esbuild 编译用户代码到 `dist/`
- 共享 esbuild 配置，与开发编译器保持一致

#### OpenAPI / Swagger

`src/lib/openapi/`（7 个文件，共约 1,600 行）：

| 模块 | 说明 |

| `types.ts` | OpenAPI 3.0.3 类型定义 |
| `collector.ts` | 路由信息收集器（在 router-loader 中集成） |
| `schema-converter.ts` | schema-dsl DSL → JSON Schema 自动转换 |
| `operation-id.ts` | 操作 ID 自动生成（method + path → camelCase） |
| `generator.ts` | OpenAPI 文档生成器 |
| `swagger-ui.ts` | Swagger UI HTML 页面（CDN 加载） |
| `index.ts` | 公共导出 |

提供两个端点：
- `GET /docs`：Swagger UI 交互式文档页面
- `GET /openapi.json`：OpenAPI 3.0.3 规范文档

### Phase 2B：热重载

**目标**：三层 Soft Reload（Tier 1/2 软重载 + Tier 3 冷重启）。

#### HotSwappableHandler（原子替换）

`src/lib/dev/hot-swappable-handler.ts`（173 行）：

- 将 HTTP 请求 handler 包装为可原子替换的代理
- `swap(newHandler)`：替换时保证请求级隔离（进行中的请求不受影响）
- 记录 `reloadCount` / `lastSwapTime` 供监控使用

#### CacheInvalidator（缓存清除）

`src/lib/dev/cache-invalidator.ts`（364 行）：

- 构建 `require.cache` 的反向依赖图（BFS）
- 精确清除变更文件及其依赖链的模块缓存
- 安全边界：不清除 `node_modules/` 和 config 类模块
- 级联爆炸检测：变更影响 >80% 模块时自动降级为冷重启

#### MemoryMonitor（内存监控）

`src/lib/dev/memory-monitor.ts`（348 行）：

- 堆内存快照滑动窗口（默认 10 次采样）
- 增长趋势线性回归检测
- 节流报告（避免日志刷屏）
- 超阈值时触发高内存警告

#### ServiceReloader（服务重载）

`src/lib/dev/service-reloader.ts`（430 行）：

- 选择性重建 service 实例（仅重载变更的服务文件）
- `filePathToServiceKeys` 嵌套 key 映射（支持多级服务目录）
- 旧实例 `dispose()` + 回滚机制（新实例初始化失败时恢复旧实例）

#### RouteReloader（路由重载）

`src/lib/dev/route-reloader.ts`（516 行）：

- Fresh Adapter 策略：创建新 adapter 实例，重新注册所有路由
- 完整重载流程：内置中间件 → 插件全局中间件 → 路由 → 404 handler
- 通过 `HotSwappableHandler.swap()` 原子替换入口 handler

#### I18nReloader（国际化热替换）

`src/lib/dev/i18n-reloader.ts`（390 行）：

- locale 文件变更时热替换翻译内容
- 格式校验：仅处理合法 locale 代码文件（`zh-CN.json` / `en.json` 等）
- `configureI18n` 回调解耦：i18n 重新加载时回调通知其他模块

#### Access Log 中间件

`src/lib/middlewares/access-log.ts`（88 行）：

- 洋葱模型 after-middleware：请求前记录开始时间，响应后记录耗时
- 自动读取 `requestContext.requestId`（pino mixin 注入）
- `skipPaths` Set O(1) 查找（过滤健康检查等路径）
- 开发模式紧凑单行格式，生产模式结构化 JSON

#### SoftReloader（热重载编排器）

`src/lib/dev/soft-reloader.ts`（613 行）：

- 完整 Tier 1/2 流程编排：
  - Tier 1（路由/服务变更）：增量编译 → 缓存清除 → 服务重载 → 路由重载 → 原子替换
  - Tier 2（新增/删除文件）：全量重编译 → 同 Tier 1 流程
  - Tier 3（配置/插件变更）：降级冷重启
- 并发保护锁：同一时间只执行一次 Soft Reload
- pending queue 去重合并：高频保存时合并多次变更为一次重载
- 级联爆炸自动降级

### Phase 3：企业级

**目标**：Cluster 多进程 + Multi-Adapter + MonSQLize 内置插件。

#### Cluster 多进程

`src/lib/cluster/`（7 个文件）：

| 文件 | 说明 |
|------|------|
| `master.ts` | ClusterMaster：串行 fork + 指数退避重启 + Rolling Restart + 优雅关闭 |
| `worker.ts` | workerMain：bootstrap + IPC 响应 + 心跳 + 指标上报 + 内存阈值检测 |
| `worker-count.ts` | CPU 核数感知的 Worker 数量计算 |
| `pid-file.ts` | PID 文件读写（用于 CLI 管理命令定位 Master 进程） |
| `cluster-checks.ts` | 平台兼容性检测（Windows cluster 限制说明） |
| `ipc-types.ts` | IPC 消息类型定义（ready / heartbeat / metrics / request-restart 等） |
| `index.ts` | 公共导出 |

**信号矩阵**：
- `SIGTERM` / `SIGINT`：优雅关闭（等待在途请求 + Worker 退出）
- `SIGHUP`：触发 Rolling Restart（逐个替换 Worker，零停机）
- `SIGUSR2`：手动触发 Rolling Restart

#### CLI 管理命令

`src/cli/stop.ts` / `src/cli/reload.ts` / `src/cli/status.ts`：

| 命令 | 说明 |
|------|------|
| `vext stop` | 读取 PID 文件 → 发送 SIGTERM → 轮询等待退出（30s 超时） |
| `vext reload` | 发送 SIGHUP 触发 Rolling Restart（Windows 退化提示） |
| `vext status` | 三状态输出：⚪ not running / 🔴 stale / 🟢 running + /health 端点探测 |

三命令均支持 `--pid-file` 自定义路径。

#### Multi-Adapter

`src/adapters/fastify/` + `src/adapters/express/` + `src/adapters/koa/` + `src/adapters/native/`：

| Adapter | 说明 | RPS（JSON 场景）|
|---------|------|:------:|
| Hono | 基于 @hono/node-server，Web 标准 API | ~23K |
| Fastify | routerOptions 替代顶层选项（修复 FSTDEP022）| ~51K |
| Express | 手动 collectRawBody + 延迟注册 fallbacks | ~14K |
| Koa | 内置轻量级路由匹配器，`ctx.respond=false` bypass | ~43K |
| **Native** | **http.createServer + find-my-way trie router，零依赖** | **~71K** |

**默认 adapter**：`native`（最高 RPS，零外部 HTTP 框架依赖）

所有 adapter 通过按需动态 `import()` 加载（用户仅需安装所选 adapter 对应的框架包）。

#### MonSQLize 内置默认插件

`src/lib/plugins/monsqlize/`（5 个文件）：

- **条件加载**：仅当 `config.database` 存在时启用，无配置零开销
- **连接封装**：`createConnection()` 统一返回 `collection / db / model / client` 四种访问方式
- **Model 自动加载**：扫描 `src/models/` 目录，自动注册到 `app.services` 或指定命名空间
- **onClose 清理**：优雅关闭时自动断开数据库连接
- **配置映射**：支持缓存 L1/L2、多连接池、慢查询日志、日志桥接

## 📊 性能数据

基于 autocannon（5 轮中位数选取，connections=100，duration=10s）：

| Adapter | Raw RPS | Vext RPS | Overhead |
|---------|:-------:|:--------:|:--------:|

| Fastify | 79,900 | 50,806 | 36% |
| Koa | 66,000 | 43,300 | 34% |
| Hono | 41,800 | 23,600 | 44% |
| Express | 15,700 | 13,600 | 13% |

平均 overhead **19-25%**，符合全功能框架预期（含 body parser + response wrapper + AsyncLocalStorage + 中间件链执行器）。
