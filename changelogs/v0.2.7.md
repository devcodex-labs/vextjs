## Dependency Update

### DEPS-01: monsqlize `^1.1.8` → `^1.2.0`

**问题背景**

monsqlize `≤1.1.9` 存在一个 Bug：`findPage` 的 `projection` 参数被完全静默忽略，无论传入何种投影配置，始终返回文档的全字段。

vext 通过 `app.db.collection('name').findPage(...)` 将该 API 完整暴露给用户。vext 的 TypeScript 类型体系也重导出了 `FindPageOptions`，其中已声明 `projection` 字段（继承自 `FindOptions`），形成**类型承诺与运行时实现不一致**的问题。

**影响场景**

任何在 vext 应用中使用以下模式的代码，在 monsqlize ≤1.1.9 下均无法按预期工作：

```typescript
// ❌ monsqlize ≤1.1.9：projection 静默忽略，返回全字段
const result = await app.db.collection('orders').findPage({
  query: { status: 'paid' },
  sort: { createdAt: -1 },
  limit: 20,
  projection: { orderId: 1, amount: 1 }  // 被完全忽略
});

// ✅ monsqlize ≥1.2.0（本次修复后）：projection 正确生效
const result = await app.db.collection('orders').findPage({
  query: { status: 'paid' },
  sort: { createdAt: -1 },
  limit: 20,
  projection: { orderId: 1, amount: 1 }  // ✅ 只返回 orderId / amount / 排序字段
});
```

**monsqlize v1.2.0 修复内容**

| 变更 | 说明 |
|------|------|
| `buildPagePipelineA` 新增 `projection` 参数 | 聚合管道末段注入 `$project` 阶段 |
| `buildEffectiveProjection` 辅助函数 | 自动保护排序字段，确保游标锚点提取不受投影影响 |
| 三条路径全覆盖 | 游标分页 / 流式模式 / offsetJump 跳页均已支持 |
| 8 个新增测试用例 | 覆盖包含型 / 排除型 / 数组型 / before 游标 / offsetJump / 向后兼容等场景 |

**为什么使用 `^1.2.0` 而非精确锁定**

- `^1.2.0` 允许接收 monsqlize 后续 patch 修复（如 `1.2.1`），更安全
- 精确锁定 `1.2.0` 会屏蔽未来的安全和稳定性修复，不推荐
