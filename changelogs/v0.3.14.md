# v0.3.14 - 2026-06-04

## Highlights

- 升级路由级响应缓存运行时到 `response-cache-kit@^1.2.0`，底层解析到 `cache-hub@2.2.0`。
- 新增 `config.cache.cacheHub` 用户配置入口，支持 Memory、Redis、MultiLevel、lease 与 distributed tag invalidation。
- 保留旧 Memory 快捷配置 `maxEntries`、`maxMemory`、`cleanupInterval`，并明确 `cacheHub` 优先级。
- 应用 shutdown 时会在用户 `onClose` 钩子执行后关闭响应缓存运行时资源，覆盖 Redis/MultiLevel 连接清理。
- 扩展配置加载校验，启动期 fail fast 拒绝非法 `cacheHub`、lease、distributed 与 Redis/MultiLevel 字段。
- 补齐 README 与 website 响应缓存文档，说明完整配置、用户/租户隔离、缓存击穿保护和 namespace safe clear。
- 在 `vext-test` 外部消费者项目中接入 Memory `cacheHub` 配置并完成验证。

## Compatibility

- 旧的 `config.cache.defaultTtl`、`maxEntries`、`maxMemory` 写法继续可用。
- vext 仍不开放自定义 Store；底层能力由 `response-cache-kit/cache-hub` 承接。
- Redis/MultiLevel 场景需要业务项目自行安装并配置可用 Redis 客户端或 Redis URL。
