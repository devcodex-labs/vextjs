## Bug Fixes

### BUG-031: dev 模式子目录 i18n 语言包未加载

**问题背景**

vextjs 支持两种 i18n 文件组织模式：

- **Mode A（平铺文件）**：`src/locales/zh-CN.ts` — 由 `loadI18n()` 扫描加载
- **Mode B（子目录）**：`src/locales/user/zh-CN.cjs` — 由 `schemaAdapter.configure({ i18n: path })` 递归扫描加载

生产模式（`bootstrap.ts`）两种 Mode 均支持：Mode A 优先，若无平铺文件则回退 Mode B。

**根因**

`dev-bootstrap.ts` 的 i18n 加载逻辑只实现了 Mode A，**缺少 Mode B 子目录回退**。当项目使用 Mode B 组织语言文件时，`loadI18n()` 扫描到目录项（而非语言文件）后返回空数组，dev-bootstrap 直接跳过，导致所有 locale key 均未注册到 `Locale` 单例。

**表现**

```
// 期望（生产模式正常）
{ code: 60201, message: "User not found" }

// 实际（dev 模式异常）
{ code: 400, message: "user.not_found" }
```

调用 `app.throw(404, "user.not_found")` 时，`Locale.getMessage("user.not_found")` 因找不到注册的 key 而返回原始字符串，`I18nError` 中 `code === originalKey`，最终 `HttpError` 的 `code` 字段为 `undefined`，框架降级输出 HTTP 状态码。

**修复**

在 `dev-bootstrap.ts` 的 i18n 加载步骤中补充 Mode B 回退，与生产 `bootstrap.ts` 保持一致：

```typescript
const loadedLocales = await loadI18n(localesDir, app.logger);
if (loadedLocales.length > 0) {
  // Mode A: 平铺文件加载成功
  app.logger.info(`[vext dev] i18n locales loaded: ${loadedLocales.join(", ")}`);
} else {
  // Mode B fallback: 子目录扫描
  const entries = readdirSync(localesDir, { withFileTypes: true });
  const hasSubDirs = entries.some((e) => e.isDirectory());
  if (hasSubDirs) {
    schemaAdapter.configure({ i18n: localesDir });
    app.logger.info(`[vext dev] i18n locales loaded (subdirectory mode): ...`);
  }
}
```

修复后启动日志示例：
```
[vext dev] i18n locales loaded (subdirectory mode): auth, blog, core, user
```
