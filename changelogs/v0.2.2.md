## New Features

### OPENAPI-013: Scalar 本地资产自动服务（无 CDN 回退）

**背景**：

vext v0.2.x 中，`/docs` 页面加载 Scalar API Reference UI 时默认通过 jsDelivr CDN 拉取 JS 文件：

```html
<script
  src="https://cdn.jsdelivr.net/npm/@scalar/api-reference"
  crossorigin
></script>
```

这在以下环境中导致文档页白屏或极慢加载：

- **中国大陆**：jsDelivr 节点不稳定，P50 延迟 3~8 秒，部分时段完全不可用
- **企业内网**：无法访问外部 CDN
- **离线/隔离环境**：Docker 容器无网络出口、K8s 内网集群等

**变更内容**：

新增 `src/lib/openapi/scalar-assets.ts` 模块，当 `openapi.enabled: true` 时强制本地服务 Scalar JS：

**启动阶段自动执行流程**：

```
1. 用户配置了 scalar.cdnUrl？
   ├─ 是 → 使用用户配置（不做任何检测或安装）
   └─ 否 ↓
2. @scalar/api-reference 已安装？
   ├─ 是 → 读取 dist/browser/standalone.js（或 fallback dist/index.js）
   │       → 内存缓存 → 注册 GET /_vext/scalar.js 路由
   └─ 否 ↓
3. 检测包管理器（pnpm-lock.yaml / yarn.lock / bun.lockb → npm 默认）
   → execSync 执行安装命令（stdio: 'inherit'，进度对用户可见）
   → 安装成功 → 读取文件 → 注册路由
   → 安装失败 → throw Error（含手动安装命令提示，不静默降级）
```

**请求阶段**：

```
GET /docs → HTML（<script src="/_vext/scalar.js">）
GET /_vext/scalar.js → 返回内存缓存的 JS（Content-Type: application/javascript）
                        Cache-Control: public, max-age=3600
```

**性能对比**：

## Bug Fixes (v0.2.2)

### BUG-FIX-001: `@scalar/api-reference` exports 字段阻止 `./package.json` 解析

**现象**：`@scalar/api-reference` ≥ 1.x 的 `package.json` 设置了严格的 `exports` 字段，
不包含 `"./package.json"` 导出项。`resolveScalarStandalonePath()` 中的
`require.resolve('@scalar/api-reference/package.json')` 因此抛出
`ERR_PACKAGE_PATH_NOT_EXPORTED`，函数返回 `null`，框架误判为"包未安装"并进入
`autoInstallScalar()` 执行 `execSync npm install`，导致服务器启动**永久挂起**。

**根本原因**：单一解析策略（`./package.json`）无法应对使用严格 `exports` 的包。

**修复方案**：引入双策略包路径解析（`resolveScalarStandalonePath` v2）：

```
策略 1（兼容旧版 / 无严格 exports 限制的包）：
  require.resolve('@scalar/api-reference/package.json')
  → 直接拿到 pkgDir

策略 2（应对 @scalar ≥ 1.x 严格 exports）：
  require.resolve('@scalar/api-reference')   → 取主入口路径
  findPackageRoot(mainEntry)                  → 向上遍历目录树（最多 5 层）
                                                查找含 package.json 的目录
```

新增内部函数 `findPackageRoot(filePath)`：从给定路径向上最多遍历 5 层，
找到第一个含 `package.json` 的目录即为包根，用于策略 2 路径反推。

**影响范围**：`src/lib/openapi/scalar-assets.ts`（`resolveScalarStandalonePath` + 新增 `findPackageRoot`）

**验证**：

- 单元测试新增场景 9（2 个用例），覆盖 ERR_PACKAGE_PATH_NOT_EXPORTED + fallback dist/index.js 两种情形
- E2E 实测：`@scalar/api-reference` 1.x 安装后服务器正常启动，日志输出 `[openapi] Scalar 资产: /_vext/scalar.js (本地模式)`

### BUG-FIX-002: vext-test `__dirname` 在 `tsx/esm` 运行时未定义

**现象**：`vext start`（无 `dist/`，使用 `tsx/esm` 运行 TypeScript）时，
`src/config/default.ts` 中的 `path.join(__dirname, "../locales")` 抛出
`ReferenceError: __dirname is not defined in ES module scope`，服务器无法启动。

**根本原因**：

- `vext dev` 使用 esbuild 将 TypeScript 编译为 CJS，esbuild 自动在输出顶部注入 `__dirname`
- `vext start`（无编译产物）使用 `--import tsx/esm` 以 ESM 模式运行，ESM 中 `__dirname` 不可用

**修复方案**：将 `path.join(__dirname, "../locales")` 替换为 `path.join(process.cwd(), "src/locales")`。
`process.cwd()` 始终是执行 `vext start/dev` 命令时的项目根目录（即 vext-test/），
在两种运行模式下均可靠可用，无 ESM/CJS 兼容问题。

**影响范围**：`vext-test/src/config/default.ts`

## Implementation Notes

### 包管理器检测优先级

通过检查用户项目根目录（`process.cwd()`）中的 lockfile 判断：

```
pnpm-lock.yaml → pnpm add @scalar/api-reference
yarn.lock       → yarn add @scalar/api-reference
bun.lockb       → bun add @scalar/api-reference
（默认）        → npm install @scalar/api-reference --no-save
```

npm 使用 `--no-save` 避免修改用户的 `package.json`。pnpm/yarn/bun 会将包写入 lockfile，建议在生产镜像构建阶段预先安装。

### 包路径双策略解析（v0.2.2，BUG-FIX-001 修订）

使用 `createRequire(join(process.cwd(), 'package.json'))` 而非 `createRequire(import.meta.url)` 解析包路径。

原因：vext 可能以 `"vextjs": "file:../vext"` 本地依赖方式使用（如开发环境）。Node.js 默认跟随符号链接，`import.meta.url` 会指向 vext 真实磁盘路径而非用户项目目录，导致无法找到用户项目安装的包。`process.cwd()` 始终是用户执行 `vext dev/start` 时的项目根目录，可以可靠地找到用户项目的 `node_modules/`。

**v2 双策略补充（BUG-FIX-001）**：现代包（如 `@scalar/api-reference` ≥ 1.x）在 `package.json` 中设置了严格的 `exports` 字段，不暴露 `./package.json` 子路径，导致 `require.resolve('./package.json')` 抛出 `ERR_PACKAGE_PATH_NOT_EXPORTED`。解决方案：降级到解析主入口（`require.resolve('@scalar/api-reference')`），再通过 `findPackageRoot()` 向上遍历目录树（最多 5 层）找到包根目录。

## Migration Guide

### 无破坏性变更（Breaking Changes: None）

v0.2.2 对现有用户完全透明，无需任何配置修改。

### 生产环境推荐配置

在构建镜像时预先安装 `@scalar/api-reference`，避免容器启动时触发网络安装：

```dockerfile
# Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
# 预安装 Scalar（避免运行时自动安装）
RUN npm install @scalar/api-reference --no-save
COPY . .
RUN npm run build
CMD ["node", "dist/index.js"]
```

### 如需保留 CDN 加载（不推荐）

配置 `scalar.cdnUrl` 后框架将跳过所有本地化逻辑，使用指定地址：

```typescript
// src/config/default.ts
export default {
  openapi: {
    scalar: {
      cdnUrl: "https://cdn.jsdelivr.net/npm/@scalar/api-reference",
    },
  },
};
```
