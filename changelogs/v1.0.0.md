# vextjs v1.0.0

**Date**: 2026-08-10
**Type**: Major

## Summary

First stable `1.0.0` identity on the schema-dsl v3 / monsqlize 3.1 stack. Upstream packages are pinned to exact GA versions; public package identity moves from `0.3.26` source adaptation to a release-gated `vextjs@1.0.0`.

## Highlights

- **schema-dsl@3.0.0 / monsqlize@3.1.0** exact pins with side-effect-free schema adaptation (no `String.prototype.description` dependency).
- **Vext Runtime Launchpad** for the default `fullstack-react` scaffold: an SSR route-to-page starter with `useVextI18n`, server-provided greeting/render time, shared navigation, and responsive accessible styling.
- **Cleaner scaffold output**: `vext create` no longer adds root or directory-level placeholder `README.md` files; optional convention folders remain supported and are created with real source files.
- **Unified starter brand assets**: the shared V mark is emitted as both `public/vext-mark.svg` and `public/favicon.svg`, while the launchpad uses the same cyan/green/amber palette as the documentation logo.
- **Response header fail-fast** invalid names/values (including CRLF) throw from buffered `setHeader` / `appendHeader` on all adapters.
- **Onion deferred flush** post-`next()` header/cookie mutations land on the final response for native/express (and related adapter parity work).
- **Session / cookie / CSRF / auth / security-headers** first-party runtime contracts stabilized for production use.
- **Built-in docs renderer**, full-stack frontend (React render/SSR/deploy paths), and package composition gates for publishable artifacts.
- **Route-native browser runtime**: same-route page envelopes, generated navigation, route freshness/revalidation, persistent layouts, and local media/font asset pipelines are available without introducing a loader/action DSL or a second bundler ecosystem.
- **Clearer project preload and build defaults**: application preload source is canonical at `src/preload/**`, legacy root `preload/**` is a warning-bearing fallback, and `vext build` minifies by default with explicit diagnostic opt-outs.
- **Actionable frontend diagnostics and a production-ready starter**: route warnings identify the HTTP route and source file, initial-JavaScript metrics exclude deferred chunks, and the full-stack starter includes a branded SSR launchpad, Vext Guide link, and live local `/docs` entry.
- **I18n opt-out resilience**: the generated launchpad remains renderable when `frontend.i18n.enabled=false`, using neutral English fallback copy; the bilingual I18n guide explains the corresponding application-component pattern.
- **Documentation and release assurance**: bilingual frontend/JSCSS documentation, RSC/PPR boundary guidance, machine-readable AI artifacts, strict bilingual version checks, and website production dependency auditing are part of the release path.
- **Release preflight** source + final modes: tests, coverage, package composition, documentation source/rendered contracts, pack, isolated install, and identity-bound external consumer evidence.
- **Hono Node stream response bridge** now transfers stream ownership before pipe, preserves slow `res.download()` completion, and has a real HTTP regression test for delayed stream tails.

## Breaking / migration

See [MIGRATION.md](../MIGRATION.md):

- Do not rely on `String.prototype.description` side effects.
- `?` means optional-only; nullability is explicit (`types:string|null` or JSON Schema unions).
- Prefer `schemaAdapter.compileField(...).description(...)` for field descriptions.
