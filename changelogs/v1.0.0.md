# vextjs v1.0.0

**Date**: 2026-07-28  
**Type**: Major

## Summary

First stable `1.0.0` identity on the schema-dsl v3 / monsqlize 3.1 stack. Upstream packages are pinned to exact GA versions; public package identity moves from `0.3.26` source adaptation to a release-gated `vextjs@1.0.0`.

## Highlights

- **schema-dsl@3.0.0 / monsqlize@3.1.0** exact pins with side-effect-free schema adaptation (no `String.prototype.description` dependency).
- **Response header fail-fast** invalid names/values (including CRLF) throw from buffered `setHeader` / `appendHeader` on all adapters.
- **Onion deferred flush** post-`next()` header/cookie mutations land on the final response for native/express (and related adapter parity work).
- **Session / cookie / CSRF / auth / security-headers** first-party runtime contracts stabilized for production use.
- **Built-in docs renderer**, full-stack frontend (React render/SSR/deploy paths), and package composition gates for publishable artifacts.
- **Release preflight** source + final modes: tests, coverage, package composition, documentation source/rendered contracts, pack, isolated install, and identity-bound external consumer evidence.
- **Hono Node stream response bridge** now transfers stream ownership before pipe, preserves slow `res.download()` completion, and has a real HTTP regression test for delayed stream tails.

## Breaking / migration

See [MIGRATION.md](../MIGRATION.md):

- Do not rely on `String.prototype.description` side effects.
- `?` means optional-only; nullability is explicit (`types:string|null` or JSON Schema unions).
- Prefer `schemaAdapter.compileField(...).description(...)` for field descriptions.
