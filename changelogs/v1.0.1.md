# vextjs v1.0.1

**Date**: 2026-08-10
**Type**: Patch (documentation and release validation; no runtime changes)

## Summary

Documentation patch that rewrites the package entry `README.md` for humans and AI assistants, aligns public identity metadata after the `1.0.0` release, and keeps release-validation scripts consistent with that public contract.

`1.0.0` already shipped with correct `package.json` license/engines/homepage, but the published README remained a Chinese long-form manual with stale org/docs URLs and MIT/Node 18 badges. This release replaces that entry surface without runtime API changes.

## Highlights

- **English product README** as the npm/GitHub entry: outcome-first positioning, a three-command first success, a real route-model/request-lifecycle example, fit/boundary guidance, AI assistant links (`llms.txt`, `capabilities.json`), and stable `## CLI` anchors.
- **Cold-start command corrected** to `npx vextjs create` (package name); the installed project-local command remains `vext`.
- **Identity cleanup** in README: Apache-2.0, Node.js `>=20.19.0`, `devcodex-labs/vextjs`, `https://devcodex-labs.github.io/vextjs/`.
- **Documentation contract** checks stable README semantics and public identity while detailed frontend lifecycle contracts remain owned by bilingual topic pages.
- **Locale-specific AI indexes** keep root `llms.txt` / `llms-full.txt` English-only and publish matching Simplified Chinese indexes under `/zh/`; rendered validation proves each complete index covers its 76-page locale exactly once.
- **Version sync** for docs navbar, CLI examples, and quick-start dependency pins to `1.0.1`.
- **One version-contract implementation** shared by local CI and GitHub Actions, avoiding stale documentation paths and README patch-version assumptions.
- **CHANGELOG compare links** pointed at `github.com/devcodex-labs/vextjs`.
- **Package discovery metadata** now states the user outcome: APIs and server-rendered pages, one route model, typed contracts, and built-in docs.
- **Runtime and DX positioning** now covers route-contract outputs, opt-in `config.database` lifecycle, three-tier hot reload, React Fast Refresh, production lifecycle controls, and the Hono Node adapter boundary.
- **Typed API client** called out in Features with links to `api-client-and-contracts` / build docs.
- **Profile** release-state notes updated for published `1.0.0` vs in-tree documentation patch `1.0.1`.

## Non-goals

- No runtime API or adapter behavior changes.
- Chinese long-form docs remain on the site `/zh` locale (not a second npm README).
