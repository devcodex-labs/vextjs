## New Features

### F-01: `app.setLogger(wrapper)`

允许插件包装 logger 转发到��部日志系统（OTel Logs、Sentry 等），与 `app.setThrow()` 模式一致。

### F-02: `response.logErrors` 配置

新增 `response.logErrors` 配置项，控制 error-handler 对各类错误的日志输出：

| 配置项                           | 类型      | 默认值  | 说明                            |
| -------------------------------- | --------- | ------- | ------------------------------- |
| `response.logErrors.unknownErrors` | `boolean` | `true`  | 记录未知 500 错误（含 stack）   |
| `response.logErrors.http5xx`     | `boolean` | `true`  | 记录 HttpError 5xx（error 级别）|
| `response.logErrors.http4xx`     | `boolean` | `false` | 记录 HttpError 4xx（warn 级别） |

error-handler 日志功能（logger 注入为第三参数）向后兼容：不传 logger 时行为与之前完全一致。

### F-03: Dev Error Overlay

开发模式下（`vext dev`），浏览器请求（`Accept: text/html`）出错路由时，自动返回 HTML 错误覆盖层，包含错误类型、消息、堆栈帧等。配置项：

```typescript
export default {
  dev: {
    errorOverlay: {
      enabled: true,    // 默认开启
      theme: "dark",    // 'dark' | 'light'
      maxFrames: 25,    // 最多显示堆栈帧数
    },
  },
};
```

仅 dev 模式生效，生产模式自动忽略。API 客户端不受影响。

## Bug Fixes

### BUG-031: dev-bootstrap 中间件条件注册对齐

**问题**：`dev-bootstrap.ts` 步骤 8 的 6 个内置中间件（requestId / cors / bodyParser / rateLimit / responseWrapper / accessLog）全部无条件注册，用户在 `vext dev` 模式下配置 `cors: { enabled: false }` 等不生效。

**根因**：步骤 8 从早期版本移植，生产侧 `bootstrap.ts` 后来加了 `if (config.xxx?.enabled !== false)` 条件守卫，但未同步到 dev 侧。

**修复**：
- `dev-bootstrap.ts` 步骤 8：6 个中间件各自加条件守卫
- `builtinMwCreators`（soft reload 侧）：条件赋值（disabled → `undefined`），route-reloader 的 `if` 检查自动跳过
- `testing/index.ts`：同步加条件守卫 + 补传参数

### BUG-032: `createRequestIdMiddleware` localeConfig 参数缺失

**问题**：`dev-bootstrap.ts` 中 `createRequestIdMiddleware` 缺少第四参数 `localeConfig`，导致 dev 模式下 `store.locale` 不写入，i18n 语言解析失效。

**修复**：步骤 8 初始注册 + builtinMwCreators soft reload 侧均补传 `config.locale`。
