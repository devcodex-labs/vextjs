# v0.1.5 Changelog

**Release Date**: 2026-03-09
**Type**: Minor (Scalar API Reference + OpenAPI Pipeline + Bug Fixes + Documentation)

## Summary

This release is a major overhaul of the API documentation subsystem, replacing the Swagger UI + Redoc dual-endpoint approach with [Scalar API Reference](https://github.com/scalar/scalar) — a modern, single-page solution that combines documentation reading with interactive "Try it out" requests. It also includes 13 bug fixes (4× P0, 4× P1, 3× P2, 2× P3), SchemaConverter delegation to schema-dsl, OpenAPI pipeline integration tests, cross-repo CI automation, `x-tagGroups` automatic tag grouping, and comprehensive documentation updates.

## New Features

### x-tagGroups: Automatic Tag Grouping for Multi-Level Navigation

**Files**: `src/lib/openapi/generator.ts`, `src/lib/openapi/types.ts`, `website/docs/guide/openapi.md`

OpenAPI 3.x tags are flat by design, causing all tags to appear side-by-side in the Scalar sidebar. VextJS now automatically generates `x-tagGroups` (a vendor extension supported by Scalar and Redocly) to group tags into a two-level navigation structure based on the first-level directory under `routes/`.

- **Automatic inference**: `routes/api/users.ts` → group "Api", `routes/admin/dashboard.ts` → group "Admin"
- **Manual override**: configure `openapi.tagGroups` array to fully control grouping
- **Smart behavior**: only generated when routes span multiple top-level directories (single-group projects skip it)
- Groups are sorted alphabetically with "General" (root-level routes) always last
- 21 new unit tests covering auto-inference, config override, edge cases, and integration scenarios

### OPENAPI-008: Scalar API Reference (replaces Swagger UI + Redoc)

**Files**: `src/lib/openapi/scalar-ui.ts`, `src/lib/openapi/doc-endpoints.ts`, `src/types/app.ts`

The `/docs` endpoint now serves [Scalar API Reference](https://github.com/scalar/scalar), providing both documentation reading and interactive API testing in a single page. The previous `/swagger` endpoint and Redoc navigation bar have been removed.

New `ScalarConfig` type supports:
- 10+ themes (`purple`, `saturn`, `moon`, `mars`, `deepSpace`, etc.)
- Dark mode toggle
- `modern` / `classic` layout
- Search hotkeys
- Proxy URL for cross-origin requests
- Client language visibility control
- Custom favicon (`favicon?: string`)
- External document import (`sources?: Array<{ title?, url?, content?, slug? }>`)
- Custom CDN / local assets (`cdnUrl?: string`)

`DocEndpointsConfig` simplified to `specPath` + `docsPath` + `title` + `scalar`, removing the `ui: 'both' | 'redoc' | 'swagger'` option. `swagger-ui.ts` retained as backward-compatible stub (`registerOpenAPIRoutes` delegates to `registerDocEndpoints`).

### OPENAPI-009: Scalar Favicon Support

**File**: `src/lib/openapi/scalar-ui.ts`

`ScalarConfig` gains `favicon?: string`. When set, `generateScalarHTML()` outputs a `<link rel="icon">` tag in `<head>` with auto-detected MIME type (SVG/PNG). Allows the `/docs` page to share the same icon as the main site.

### OPENAPI-010: External OpenAPI Document Import (Multi-Document Switching)

**File**: `src/lib/openapi/scalar-ui.ts`

`ScalarConfig` gains `sources?: Array<{ title?, url?, content?, slug? }>`. Scalar UI displays a document switcher at the top. The framework's auto-generated `/openapi.json` is injected as the first source (unless already present in `sources`). Supports both URL (remote/local endpoints) and `content` (inline JSON string) formats.

### OPENAPI-011: Custom CDN / Local Assets

**File**: `src/lib/openapi/scalar-ui.ts`

`ScalarConfig` gains `cdnUrl?: string` to replace the default jsDelivr CDN address. Use cases: intranet/offline deployment (self-hosted JS files), version pinning (specific `@scalar/api-reference` version), enterprise CDN mirrors.

## Bug Fixes

### P0 BUG-011: `requestContext.getStore()` Returns `null` in User Route Handlers

**File**: `src/lib/request-context.ts`

**Problem**: ESM/CJS dual-package singleton bug. Framework adapter (ESM `dist/index.js`) calls `requestContext.run()` on instance A, but user route code compiled to CJS calls `require("vextjs")` which loads `dist/index.cjs` containing a separate `new AsyncLocalStorage()` instance B. `getStore()` on instance B returns `null`.

**Impact**: `propagateHeaders` end-to-end passthrough broken; `req.requestId` unavailable in user code.

**Fix**: Cache singleton via `globalThis[Symbol.for("vextjs.requestContext")]` — both ESM and CJS resolve to the same AsyncLocalStorage instance.

### P0 BUG-012: Pino Mixin `EMPTY_MIXIN` Shared Object Pollution

**File**: `src/lib/logger.ts`

**Problem**: Pre-allocated shared `const EMPTY_MIXIN = {}` returned from pino `mixin()` hook. Pino internally merges caller-provided structured fields into the return value via Object.assign semantics, permanently mutating the shared object. All subsequent log entries carried stale fields.

**Fix**: Return a fresh `{}` on every mixin call instead of a shared constant.

### P0 BUG-015: `vext dev` Mode OpenAPI Endpoints Return 404

**File**: `src/lib/dev-bootstrap.ts`

**Problem**: `dev-bootstrap.ts` was missing the entire OpenAPI initialization block. No `RouteMetadataCollector`, no `OpenAPIGenerator`, no `registerOpenAPIRoutes()` call.

**Fix**: Import and initialize OpenAPI subsystem in dev-bootstrap, mirroring the production bootstrap flow.

### P0 (schema-dsl) BUG-021: `enum:a,b,c` Comma-Separated Format Broken

**Files**: (schema-dsl) `src/dsl-builder.ts`, `src/dsl-adapter.ts`

**Problem**: `DslBuilder._parseSimple()` only checked for pipe `|` separator. `enum:a,b,c` was never recognized as an enum, defaulting to `{ type: 'string', exactLength: null }`.

**Fix**: Added `enum:` prefix handler before the `|` detection block, supporting both comma and pipe separators.

### P1 BUG-013: CLI `--port` / `--host` Arguments Silently Ignored

**File**: `src/lib/config-loader.ts`

**Problem**: `loadConfig()` never read `VEXT_PORT` / `VEXT_HOST` environment variables set by the CLI forked child process.

**Fix**: Added CLI environment variable override step in `loadConfig()` (priority: `DEFAULT_CONFIG < user default < env < local < CLI env vars`).

### P1 BUG-014: Windows Graceful Shutdown Failure

**Files**: `src/cli/commands/start.ts`, `src/cli/commands/dev.ts`, `src/lib/bootstrap.ts`

**Problem**: `child.kill('SIGTERM')` on Windows calls Win32 `TerminateProcess` API, immediately killing the process without executing `onClose` hooks.

**Fix**: Send IPC `{ type: 'shutdown' }` message on Windows instead of `SIGTERM`. Child process listens for IPC message and triggers graceful shutdown. 15-second timeout guard force-kills if needed. Unix behavior unchanged.

### P1 BUG-022: Hot-Reload After Route Change Causes `/docs` 404

**Files**: `src/lib/dev/route-reloader.ts`, `src/lib/dev/soft-reloader.ts`, `src/lib/dev/dev-bootstrap.ts`

**Problem**: `reloadRoutes()` creates a fresh adapter instance and re-registers routes, built-in middlewares, error/404 handlers — but did **not** re-run OpenAPI generation or re-register `/docs` and `/openapi.json` endpoints on the new adapter. After any hot-reload, those endpoints returned 404.

**Root Cause**: The OpenAPI initialization (collector creation → spec generation → doc endpoint registration) only ran once during initial `dev-bootstrap` startup. The soft-reload path (`SoftReloader.doSoftReload()` → `reloadRoutes()`) had no awareness of OpenAPI.

**Fix**:
- `ReloadRoutesOptions` now accepts optional `openapiConfig`
- `RoutesLoader` type extended to accept optional `RouteMetadataCollector` parameter
- `reloadRoutes()` creates a fresh collector, passes it to `loadRoutes()`, then generates a new OpenAPI spec and registers `/docs` + `/openapi.json` on the fresh adapter
- `SoftReloaderOptions` extended with `openapiConfig`, passed through to `reloadRoutes()`
- `dev-bootstrap.ts` wires `openapiConfig` into `SoftReloader` constructor
- 8 new unit tests covering endpoint re-registration, collector lifecycle, custom paths, backward compatibility

### P1 BUG-016: Swagger UI "No layout defined for 'StandaloneLayout'"

**File**: `src/lib/openapi/swagger-ui.ts`

**Problem**: HTML template only loaded `swagger-ui-bundle.js`, but `StandaloneLayout` requires `swagger-ui-standalone-preset.js`.

**Fix**: Properly load standalone preset, use `StandaloneLayout` with `DownloadUrl` plugin. Added search bar, alpha sorting. (Subsequently replaced by Scalar in OPENAPI-008.)

### P2 BUG-013: CLI `--port` / `--host` Not Working

See P1 BUG-013 above.

### P2 BUG-018: Swagger UI Lacked TOC Navigation

**File**: `src/lib/openapi/swagger-ui.ts`

**Problem**: Previous BUG-016 fix switched to `BaseLayout`, removing sidebar.

**Fix**: Restored `StandaloneLayout` with proper preset loading. (Subsequently replaced by Scalar.)

### P2 BUG-019: OpenAPI Response Schemas Lacked Descriptions/Examples

**File**: `src/lib/openapi/schema-converter.ts`

**Problem**: `convertDSLString()` generated JSON Schema with type/constraints only.

### P2: E2E Test Port Collision (Intermittent EADDRINUSE)

### P3 BUG-020: Routes Without `docs.responses` Only Generated Generic `$ref`

## Upgrade Guide

### From v0.1.4

1. Update dependency:
   ```json
   "dependencies": {
     "vextjs": "^0.1.5"
   }
   ```

2. If you customized Swagger UI / Redoc config, migrate to Scalar:
   ```js
   // Before (v0.1.4)
   openapi: {
     ui: 'both',
     tryItOutEnabled: true,
     docExpansion: 'list',
   }

   // After (v0.1.5)
   openapi: {
     scalar: {
       theme: 'purple',
       layout: 'modern',
     }
   }
   ```

3. `/swagger` endpoint no longer exists — use `/docs` for both reading and testing.

4. `prettySingleLine` is now `true` by default in development mode. Set `logger.prettySingleLine: false` if you prefer multi-line log output.

5. Hot-reload debounce is now `0` by default (instant reload). Set `--debounce 100` or `VEXT_DEV_DEBOUNCE=100` to restore previous behavior.
