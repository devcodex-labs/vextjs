# v0.3.5 — 2026-05-15

## 概述

本版本在原有文档口径收口基础上，继续完成一轮**运行时能力增强 + 发布收口**：

1. 保留并完成第 4、5 项问题的修复
   - `vext create` 成功提示中的文档地址改为 `https://vextjs.github.io`
   - benchmark 页面补充 Raw / Vext 的对比口径说明
2. 正式落地**项目级 preload 目录**能力
   - 应用项目现在可以直接使用项目根 `preload/`
   - 不再需要先包装成本地 npm 包才能做启动前 preload
3. 首期支持 TS preload
   - `.mjs` / `.js` / `.ts` / `.mts`
   - TS preload 会在启动前编译到 `.vext/preload/*.mjs`
4. `vext dev` 下 preload 变更会触发 cold restart
5. 完成主仓库测试、`vext-test` 真实消费方验证、文档同步与版本一致性收口

---

## Added

- 新增**项目级 `preload/` 目录**支持：`vext start` / `vext dev` / Cluster 会在项目根自动扫描 `preload/`。
- 新增项目级 preload 文件类型支持：
  - `.mjs`
  - `.js`
  - `.ts`
  - `.mts`
- 新增 **TS preload 启动前编译**：
  - `preload/*.ts` / `preload/*.mts`
  - 会在启动前编译到 `.vext/preload/*.mjs`
  - 再统一通过 `--import` 注入
- 新增 `ColdRestarter#setExtraExecArgv()`，允许 dev 模式在 cold restart 前刷新 preload 注入参数。
- `vext-test` 新增真实消费方验证夹具：
  - `preload/01-bootstrap-port.ts`
  - `preload/02-bootstrap-verbose.mjs`
  - `verify-project-preload.mjs`

---

## Changed

- `resolvePreloads()` 从同步函数升级为统一的异步解析入口，同时负责：
  - 项目级 preload 发现
  - 包级 `vext.preload` 发现
  - 聚合顺序控制
  - 绝对路径去重
- `vext dev` 在首次启动、手动重启、cold restart 前都会刷新 preload 列表，确保项目级 preload 改动能真正生效。
- `VextFileWatcher` 现在会监听项目根 `preload/` 目录；相关变更统一归类为 **cold restart**。
- 文档站与 README 已补齐以下说明：
  - 项目级 `preload/` 目录
  - TS preload 编译行为
  - `vext dev` 下 preload 变更会触发 cold restart
  - 生产部署需一起携带项目根 `preload/` 目录

## Fixed

- 修复“项目级 preload 仅存在于方案中、CLI 实际无法识别”的能力缺口。
- 修复“目录级 preload 若使用 TypeScript，`start` / Cluster 下缺少运行机制”的设计缺口。
- 修复“开发态修改 `preload/` 后不会自动生效”的开发体验缺口。
- 修复 `vext create` 成功提示中的文档地址，已从 GitHub 仓库入口更新为 `https://vextjs.github.io`。
- 修复 benchmark 页面说明不足的问题，现已明确标注 Raw / Vext 对比口径及关闭的非核心默认能力。

## Known Notes

- 项目级 `preload/` 首期仍为**非递归**目录。
- `vext build` 不会自动把项目根 `preload/` 并入 `dist/`；若生产使用项目级 preload，部署时需一并携带项目根 `preload/`，并允许生成 `.vext/preload/` 编译缓存。
- 若后续要进一步降低部署摩擦，可继续评估：
  - 递归扫描
  - 显式目录配置
  - 只读部署环境下的缓存目录策略
