## Summary

This release delivers **MonSQLize Model Hot Reload** in `vext dev` mode — modifying `src/models/` files now triggers selective Tier 2 soft reload using monSQLize v1.1.8 native `Model.redefine()` / `Model.undefine()` APIs, with automatic rollback on failure. It also fixes a bug where `route-cache` conditional caching did not set the `X-Cache: MISS` header when the condition returned false.

## Bug Fixes

### BUG-028: `dev-bootstrap.ts` — Missing monSQLize Plugin Load in Dev Mode

- **File**: `src/lib/dev/dev-bootstrap.ts`
- **Root Cause**: Dev bootstrap did not call `createMonSQLizePlugin` even when `config.database` was present, leaving `app.db` / `app.monsqlize` as `undefined` in `vext dev` mode.
- **Fix**: Added `shouldLoadMonSQLize(config)` check in dev-bootstrap; conditionally loads `createMonSQLizePlugin` using the `outDir` compiled path.
- **Impact**: `app.db` / `app.monsqlize` now correctly available during `vext dev`.

### BUG-029: `route-cache.ts` — Missing `X-Cache: MISS` on Condition Skip

- **File**: `src/lib/middlewares/route-cache.ts` (L132–134)
- **Root Cause**: When `condition(req)` returned `false` (i.e. cache should be skipped), the middleware called `await next()` and returned immediately without setting any `X-Cache` header. Clients and monitoring tools relying on `X-Cache` for cache observability received no signal.
- **Fix**: Added `res.setHeader("X-Cache", "MISS")` before `await next()` in the condition branch.
- **Test**: Updated `test/unit/route-cache.test.ts` — the assertion for "condition=false" now expects `X-Cache: MISS` to be present (previously expected it to be absent).

```diff
// route-cache.ts L131–135
if (condition && !condition(req)) {
+  res.setHeader("X-Cache", "MISS");
   await next();
   return;
}
```

## New Features

### DEV-001: MonSQLize Model Hot Reload

**New file**: `src/lib/dev/model-reloader.ts`

Selective Model definition reload triggered during Tier 2 soft reload when files under `src/models/` are modified.

#### Architecture

```
src/models/item.ts  (saved)
  ↓
esbuild recompile → .vext/dev/models/item.js
  ↓
soft-reloader invalidation set includes item.js
  ↓
model-reloader.reloadModels(app, outDir, invalidated)
  ↓  1. scanModelDirectory(.vext/dev/models/)
  ↓  2. filter: only files in invalidation set
  ↓  3. save old definitions (for rollback)
  ↓  4. require() new compiled module
  ↓  5. Model.redefine(collectionName, newDefinition)
  ↓
new requests use updated Model definition
```

#### Key Design Decisions

| Decision                                     | Rationale                                                  |
| -------------------------------------------- | ---------------------------------------------------------- |
| Uses `Model.redefine()` / `Model.undefine()` | monSQLize v1.1.8 native API; no private field access       |
| Selective reload                             | Only affected models reloaded; others kept intact          |
| Full rollback on failure                     | Any step failure triggers rollback of all affected models  |
| `deriveModelName()` reused                   | Consistent name inference with `model-loader.ts`           |
| ESM/CJS interop handling                     | Same `__esModule` double-unwrap logic as `model-loader.ts` |

#### Rollback Guarantee

| Scenario                             | Behavior                                                         |
| ------------------------------------ | ---------------------------------------------------------------- |
| `require()` of new module fails      | All affected models rolled back to old definitions               |
| `Model.redefine()` throws            | All affected models rolled back                                  |
| New model file (no prior definition) | On rollback: `Model.undefine()` removes the partial registration |
| Rollback itself fails                | Error logged per model; main error still propagated              |

#### Exported API

```typescript
export async function reloadModels(
  app: ModelReloaderApp,
  outDir: string,
  invalidated: Set<string>,
): Promise<ModelReloadResult>;

export interface ModelReloadResult {
  reloaded: number;
  unchanged: number;
  reloadedNames: string[];
}
```

#### Log Output

```
[hot-reload] model "items" reloaded
[hot-reload] models reloaded: 1 changed (3 unchanged, kept)
[hot-reload] [OK] 48ms [T1:code] (compile:3ms cache:2ms i18n:0ms mw:5ms svc:8ms model:3ms route:25ms swap:2ms) [12 modules evicted] #3
```

On failure with rollback:

```
[hot-reload] model reload failed, rolling back 1 model(s): SyntaxError: ...
[hot-reload] model rollback failed for "items": ...  (only if rollback itself fails)
```

## Upgrade Guide

### From v0.1.6

No breaking changes. This is a dev-experience and bug-fix release.

1. Update `vextjs` version in your `package.json`:

   ```json
   "vextjs": "^0.1.7"
   ```

2. If you use `condition` in route cache configuration, note that responses now include `X-Cache: MISS` when the condition skips the cache (previously no header was set). If your client code checks for the absence of `X-Cache` to detect condition-skipped responses, update accordingly.

3. Ensure `monsqlize` is at `^1.1.8` if you use Model hot reload in dev mode:
   ```json
   "monsqlize": "^1.1.8"
   ```

## Known Issues

- **TS2307 `Cannot find module 'mongodb'`**: The `types.ts` file uses `any` for the `client` field as a workaround. Root fix requires installing `@types/mongodb` or exporting explicit types from monSQLize. Tracked as low-priority tech debt.
- **Model index changes**: Index definition changes in model files require a cold restart (`Tier 3`) to propagate to MongoDB. Soft reload only updates the in-memory Model definition.
