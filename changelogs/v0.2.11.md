## Changes Summary

Built-in multipart/form-data parsing with zero external dependencies.

VextJS now supports file uploads natively. Enable with `config.multipart.enabled: true` — the body-parser will automatically parse `multipart/form-data` requests using the Node.js 18+ `Request.formData()` Web API and fill `req.files`. No third-party library required.

---

## New Features

### Built-in Multipart / file upload parsing (`multipart.enabled`)

**Overview**:

A new `enabled` field is added to `VextMultipartConfig`. When set to `true`, the body-parser middleware detects `multipart/form-data` requests and parses them automatically, populating `req.files: ParsedFile[]`.

**Usage**:

```typescript
// vext.config.ts
export default defineConfig({
  multipart: {
    enabled: true,
    maxFileSize: 10 * 1024 * 1024, // 10MB (default)
    maxFiles: 10,                  // default
    allowedMimeTypes: ['image/jpeg', 'image/png'], // optional whitelist
  },
});
```

```typescript
// src/routes/upload.ts
app.post('/upload', {
  multipart: { files: { avatar: '用户头像' } },
}, async (req, res) => {
  const file = req.files?.find(f => f.fieldname === 'avatar');
  if (!file) return res.json({ code: 400, message: 'No file uploaded' }, 400);
  // file.buffer is the complete binary content, guaranteed lossless
  res.json({ filename: file.filename, size: file.size });
});
```

**Technical details**:

- **Zero dependencies**: Uses Node.js 18+ native `Request.formData()` Web API (project already requires `engines: >=18.0.0`)
- **Dual parse paths**:
  - Hono adapter: calls `c.req.raw.formData()` directly (no Buffer round-trip, best performance)
  - Express / Fastify / Koa / Native adapters: constructs a standard `new Request(url, { body: rawBuffer, headers })` and calls `.formData()`
- **Validation**: `maxFiles` (413), `maxFileSize` (413), `allowedMimeTypes` (415) are enforced before populating `req.files`
- **Default off**: `enabled` defaults to `false`; when not enabled, multipart requests are skipped with zero performance impact

## Binary channel infrastructure (T1–T16, shipped in 0.2.11)

The following foundational changes were also included in this release (implemented prior to the built-in parsing feature):

### `req._getRawBodyBuffer()` — typed binary accessor on all adapters

`VextRequest` now officially exposes `_getRawBodyBuffer(): Promise<Buffer>` in the TypeScript interface. All 5 adapters implement it:

- **Hono**: `Buffer.from(await c.req.arrayBuffer())` — Buffer-first cache, string derived lazily
- **Express / Koa / Fastify**: returns existing pre-collected Buffer reference (zero copy)
- **Native**: `IncomingMessage` stream read once into Buffer; string derived lazily

Previously, plugins used `(req as any)._getRawBodyBuffer()`. This is now unnecessary — the method is on the public interface with full type inference.

### `req.files` — typed file list on `VextRequest`

```typescript
interface VextRequest {
  files?: ParsedFile[] // populated by body-parser when multipart.enabled = true
}
```

### `ParsedFile` interface

```typescript
interface ParsedFile {
  fieldname: string
  filename: string
  mimetype: string
  buffer: Buffer
  size: number
}
```

### `VextMultipartConfig` / `MultipartRouteConfig` types (`src/types/app.ts`)

- `VextConfig.multipart?: VextMultipartConfig` — global multipart configuration
- `RouteOptions.multipart?: MultipartRouteConfig` — per-route file field declaration (used by OpenAPI generator)

### OpenAPI `multipart/form-data` requestBody generation

When a route declares `multipart: { files: { avatar: '...' } }`, the OpenAPI generator now emits:

```yaml
requestBody:
  required: true
  content:
    multipart/form-data:
      schema:
        type: object
        properties:
          avatar:
            type: string
            format: binary
```

### Fastify `bodyLimit` auto-linking

`bodyLimit` now defaults to `Math.max(multipart.maxFileSize, 1MB)` when `multipart.maxFileSize` is configured, preventing Fastify from rejecting large file uploads with 413 before they reach the vext middleware chain.

## Breaking Changes

None. All changes are additive and backward-compatible:

- `files` field is optional (`?`) on `VextRequest`
- `multipart.enabled` defaults to `false` — existing applications are unaffected
- `_getRawBodyBuffer()` was previously an untyped internal method; adding it to the interface is a non-breaking type improvement
