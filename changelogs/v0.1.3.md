# v0.1.3 - 关键 Bug 修复

**发布日期**: 2026-03-05
**版本类型**: Patch Release
**重要性**: ⭐⭐⭐⭐ — P0 + P1 级 Bug 修复，生产必须升级

---

## 🎯 核心主题

修复两个影响生产可用性的关键 Bug：

- **BUG-004 (P0)**：用户配置的中间件白名单丢失，导致路由级中间件全部报"未注册"错误
- **BUG-005 (P1)**：`app.fetch` 在路由闭包中为 `undefined`，服务间调用全部失败
- **BUG-003 (P1)**：Windows 终端 hot-reload 日志 emoji 乱码

---

## ✅ 变更清单

### Bug 修复

#### BUG-004 (P0)：`config-loader` `deepMerge` 跳过 `middlewares` 键

**根因**：`deepMerge(DEFAULT_CONFIG, userDefaultConfig)` 内部的 `patchMiddlewares` 设计
仅用于 env/local overlay 层合并，跳过了顶层 `middlewares` 键的合并。
当用户在 `src/config/default.ts` 中声明路由级中间件白名单时，`deepMerge` 结果中
`middlewares` 为空数组，`loadMiddlewares` 收到空列表，导致所有路由级中间件报
`Middleware "auth" is not registered` 错误。

**修复**：`deepMerge` 之后手动合并 `userDefaultConfig.middlewares`，
确保用户声明的中间件白名单不丢失。

**影响文件**：`src/lib/config-loader.ts`

#### BUG-005 (P1)：`app.fetch` 在路由 handler 闭包中为 `undefined`

**根因**：`bootstrap.ts` 中 `app.fetch = createVextFetch(...)` 的赋值位于
`loadRoutes()` 之后。而 `executeRouteFactory` 在 `loadRoutes` 阶段将 `app` 的
属性拷贝到 collector 代理对象——此时 `app.fetch` 尚未赋值，路由 handler 闭包中
捕获的 `app.fetch` 为 `undefined`，调用时报
`TypeError: app.fetch is not a function`。

**修复**：将 `app.fetch` 挂载语句移到 `loadRoutes()` 调用之前。

**影响文件**：`src/lib/bootstrap.ts`、`src/lib/dev/dev-bootstrap.ts`

#### BUG-003 (P1)：Windows 终端 hot-reload 日志 emoji 乱码

**根因**：hot-reload 相关日志使用 Unicode emoji（✅ / ❌）作为状态标记，
在 Windows PowerShell 非 UTF-8 代码页（如 GBK/cp936）下显示为乱码方块。

**修复**：将所有 hot-reload 状态 emoji 替换为 ASCII 安全标记：

- `✅` → `[OK]`
- `❌` → `[FAIL]`

**影响文件**：`src/lib/dev/soft-reloader.ts`、`src/lib/dev/cold-restarter.ts`

### 功能增强

#### Access Log 开发模式紧凑格式

**变更**：access-log 中间件在 `dev` 模式下改为紧凑单行格式，
避免 pino-pretty 将结构化字段展开为多行输出，影响日志可读性。

**格式**（开发模式）：

```
[17:53:26.174] INFO: GET /api/users 200 45ms | 127.0.0.1
```

生产模式保留原有结构化 JSON 日志格式（含完整字段）。

**影响文件**：`src/lib/middlewares/access-log.ts`

## ⬆️ 升级指南

从 v0.1.2 升级：

```bash
npm install vextjs@0.1.3
```

**无 Breaking Change**，直接升级即可。

若你在使用路由级中间件（`src/config/default.ts` 中配置了 `middlewares` 字段）
且遇到 `Middleware "xxx" is not registered` 错误，升级后该问题将自动修复。

若你在路由 handler 中使用了 `app.fetch` 且遇到 `TypeError: app.fetch is not a function`，
升级后该问题将自动修复。
