## Changes Summary

This patch integrates MonSQLize v1.2.1, which includes critical performance improvements and bug fixes for model instance creation.

---

## Dependencies Updated

### MonSQLize `1.2.0` → `1.2.1`

**Bug Fixes**:
- ✅ `msq.model()` instance caching (eliminates redundant `createIndexes` commands on each call)
- ✅ Removed duplicate `_createIndexes` method definition
- ✅ Cache invalidation on `Model.redefine()` / `Model.undefine()`
- ✅ Cache cleanup on connection close

**Type Completeness**:
- ✅ Added `model()` and `collection()` method type declarations in `types/monsqlize.ts`

**Documentation**:
- ✅ Updated caching behavior documentation in `docs/model.md` and `docs/connection.md`

**Performance Impact**:
- 🚀 ~100x reduction in `createIndexes` commands/sec under high QPS
- 🚀 ~O(1) model() call overhead (Map cache hit vs full ModelInstance construction)

---

## How This Affects vext

MonSQLize v1.2.1 brings no breaking changes and is fully backward compatible. All existing model access patterns work without modification, but now with significantly reduced overhead due to instance caching.

### Before v1.2.1:
```javascript
const User = msq.model('users');  // Creates new ModelInstance → triggers createIndexes
const User2 = msq.model('users'); // Creates another new instance → triggers createIndexes again
```

### After v1.2.1:
```javascript
const User = msq.model('users');   // Creates new ModelInstance → triggers createIndexes (once)
const User2 = msq.model('users');  // Returns cached instance → no overhead
```
