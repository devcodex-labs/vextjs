# v0.1.8 - 脚手架版本修复 + 发版流程加固

**Release Date**: 2026-03-19
**Type**: Bug Fix + Process Improvement
**Tests**: 2,233 passed (unit), vext-test 150/150 passed (100%)

## Summary

This release fixes a **critical scaffold bug** (BUG-030) where `vext create` generated a `package.json` with `"vextjs": "^1.0.0"` — a version that does not exist on npm — causing `npm install` to fail 100% of the time for every newly created project.

The root fix replaces the hardcoded version with a dynamic `readVextVersion()` function that reads the framework's own `package.json` at runtime (same `createRequire` pattern as `printVersion()`), ensuring the scaffold always writes the correct installed version. Fallback is `"latest"` if the read fails.

Two process improvements are also included: the `printVersion()` fallback is updated from a stale hardcoded version to the semantic `"vunknown"`, and `RELEASE-CHECKLIST.md` is updated to include a `src/cli/create.ts` smoke test step — closing the process gap that allowed BUG-030 to go undetected across multiple releases.

## Bug Fixes

### BUG-030: `create.ts` — Scaffold Writes Non-Existent `vextjs@^1.0.0` Version

- **File**: `src/cli/create.ts` (L403, `generatePackageJson`)
- **Root Cause**: During Phase 4 (scaffold implementation), the `vextjs` dependency in the generated `package.json` was hard-coded as `"^1.0.0"` — a forward-looking placeholder anticipating that users would use the scaffold after vext reached v1.0.0. The project is currently at `0.x` pre-release phase, making this version non-existent on npm.
- **Impact**: Every user running `vext create <name>` (without `--skip-install`) receives an `npm install` failure:
  ```
  npm error notarget No matching version found for vextjs@^1.0.0
  ```
  100% reproducible. The scaffold feature was completely unusable.
- **Fix**: Added `readVextVersion()` async function that dynamically reads the version from the framework's own `package.json` using `createRequire(import.meta.url)`, returning `^${version}`. The version is threaded through the call chain `createCommand → generateProject → getTemplateFiles → generatePackageJson` as a `vextVersion: string` parameter. On read failure, fallback is `"latest"` (safer than writing a potentially stale hardcoded version).

```diff
// src/cli/create.ts

+async function readVextVersion(): Promise<string> {
+  try {
+    const { createRequire } = await import("node:module");
+    const require = createRequire(import.meta.url);
+    const pkg = require("../../package.json") as { version: string };
+    return `^${pkg.version}`;
+  } catch {
+    return "latest";
+  }
+}

 async function generateProject(
   targetDir: string,
   options: CreateOptions,
+  vextVersion: string,
 ): Promise<void> { ... }

 function getTemplateFiles(
   options: CreateOptions,
+  vextVersion: string,
 ): Record<string, string> { ... }

 function generatePackageJson(
   name: string,
   language: "ts" | "js",
   adapter: string,
+  vextVersion: string,
 ): string {
   const deps: Record<string, string> = {
-    vextjs: "^1.0.0",
+    vextjs: vextVersion,
     ...ADAPTER_DEPS[adapter],
   };
 }
```

- **Design Note**: The fix is intentionally consistent with the existing `printVersion()` implementation in `src/cli/index.ts`, which already used `createRequire` for dynamic `package.json` reading. This ensures both version-related CLI features use the same pattern.

## Changed

### CHORE-001: `printVersion()` Fallback — `"v0.1.0"` → `"vunknown"`

- **File**: `src/cli/index.ts` (L167, `printVersion()` catch branch)
- **Change**: The error fallback output was `"vextjs v0.1.0"` (stale since v0.1.1). Updated to `"vextjs vunknown"` to semantically indicate "version information unavailable" rather than misleading users with an outdated hardcoded version.
- **Trigger Condition**: This fallback only executes when `../../package.json` cannot be read — an extremely rare edge case that occurs only on abnormal path configurations. Real-world impact is negligible.

```diff
  } catch {
-   console.log("vextjs v0.1.0");
+   console.log("vextjs vunknown");
  }
```

### CHORE-002: `RELEASE-CHECKLIST.md` — Add `src/cli/create.ts` Check Item

- **File**: `RELEASE-CHECKLIST.md` (「必须更新」section)
- **Change**: Added a new mandatory checklist item for `src/cli/create.ts` with a smoke test procedure. Because `readVextVersion()` now reads dynamically, no manual version string update is required — but a smoke test should confirm the dynamic read works correctly after each release.
- **Process Gap Analysis**: BUG-030 persisted across multiple releases because `src/cli/create.ts` was absent from the checklist. Even a developer who followed the checklist perfectly would not have caught the issue. The new item closes this gap.

```markdown
- [ ] **`src/cli/create.ts`** — `generatePackageJson` 中 `vextjs` 依赖版本（已改为动态读取，
      确认 `readVextVersion()` 正常工作）
      smoke test：`vext create test-smoke --skip-install`，检查生成的 `package.json`
      中 `vextjs` 版本与 `package.json` 当前版本一致，完成后删除 `test-smoke/`
```

## Upgrade Guide

### From v0.1.7

No breaking changes. This is a bug-fix and process-improvement release.

1. Update `vextjs` version in your `package.json`:

   ```json
   "vextjs": "^0.1.8"
   ```

2. If you previously used `vext create` and received an `npm install` error about `vextjs@^1.0.0` not found, re-run `vext create` after upgrading to v0.1.8. The generated `package.json` will now contain the correct version.
