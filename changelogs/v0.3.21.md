# v0.3.21 - 2026-06-10

## Changed

- `vext start` now treats TypeScript projects as build-only: missing or incomplete `dist/` output fails fast with a `vext build` / `vext dev` hint instead of attempting a `tsx/esm` source fallback.
- `vext dev` keeps typegen as the blocking preflight step and runs TypeScript semantic diagnostics asynchronously by default. Use `--strict-preflight` or `VEXT_DEV_STRICT_PREFLIGHT=1` to restore blocking diagnostics.
- `vext dev` now exposes `--startup-profile` / `--startup-profile-json` for startup timing, writes route manifests during dev reloads, and defers OpenAPI spec generation out of the ready-critical path.
- `vext typegen` now writes generated declarations under `.vext/types/` with `src/types/generated/index.d.ts` as the committed compatibility shim; service and app-extension manifests live under `.vext/manifest/`.
- `vext doctor routes` can read cached `.vext/manifest/routes.json` by default and use `--refresh` when a fresh route scan is needed.

## Fixed

- Removed the `ts-morph` runtime dependency from dev preflight/typegen/doctor paths; service dependency checks, app-extension discovery, and route diagnostics now use lightweight path/text scanners.
- Added conservative dev compile cache reuse so unchanged source sets can skip the initial `.vext/dev` cleanup and rebuild.
- `vext build --typecheck` now refreshes generated declarations and route/service manifests before running `tsc --noEmit`, so clean or newly scaffolded TypeScript projects do not fail on stale generated files.
- Dev route manifests written from runtime-collected metadata now map `.vext/dev/**/*.js` back to source-relative `src/routes/**` files when possible.
