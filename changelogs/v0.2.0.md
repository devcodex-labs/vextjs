## 🚀 新特性

### DEV-002：启动日志网络地址增强

**背景**：框架绑定 `host=0.0.0.0` 时，旧版只打印 `http://0.0.0.0:PORT`，用户无法直接看到可访问的实际地址（尤其是在多网卡环境下），体验较差。

**变更内容**：

当 `host=0.0.0.0`（或 `::`）时，启动日志改为多行展示：

```
[vextjs] ready
  ➜  Local:   http://localhost:3000
  ➜  Local:   http://127.0.0.1:3000
  ➜  Network: http://192.168.1.100:3000
  ➜  Network: http://10.0.0.5:3000
```

dev 模式下：

```
[vext dev] ready (soft reload enabled)
  ➜  Local:   http://localhost:3000
  ➜  Local:   http://127.0.0.1:3000
  ➜  Network: http://192.168.1.100:3000
```

具体 IP（非 0.0.0.0）场景维持原有单行输出不变：

```
[vextjs] ready on http://127.0.0.1:3000
```

**实现细节**：

- 新增内部工具模块 `src/lib/utils/network.ts`，提供：
  - `getNetworkAddresses()` — 通过 `os.networkInterfaces()` 枚举所有非 loopback IPv4 地址
  - `printReadyLog()` — 根据监听地址决定输出格式，无可用网卡时优雅降级（只输出 Local 双行）
- 生产模式 `bootstrap.ts` 与 dev 模式 `dev-bootstrap.ts` 共用同一实现
- 零新增外部依赖（仅使用 Node.js 内置 `os` 模块）
- 新增单元测试 `test/unit/lib/network.test.ts`（17 个测试用例），覆盖：
  - `getNetworkAddresses()` 多网卡/无网卡/IPv6 过滤场景
  - `printReadyLog()` 全量模式/具体 IP 模式/suffix/降级场景

**影响范围**：

- `src/lib/utils/network.ts`（新增）
- `src/lib/bootstrap.ts`（修改启动日志）
- `src/lib/dev/dev-bootstrap.ts`（修改启动日志）
- 向后兼容：具体 IP 模式输出不变；仅 `0.0.0.0` / `::` 模式的日志格式发生变更（非 API BC）

## 🐛 Bug 修复

### BUG-032：`buildMonSQLizeConfig` 中 `useMemoryServer` 字段位置错误

**问题描述**：

配置了 `database.useMemoryServer: true` 的 vext 项目，在无真实 MongoDB 实例的环境下（如纯测试环境、CI），框架启动时报错：

```
MongoServerSelectionError: connect ECONNREFUSED ::1:27017, connect ECONNREFUSED 127.0.0.1:27017
```

**根因分析**：

`buildMonSQLizeConfig()` 将 `useMemoryServer: true` 写入了 MonSQLize 构造函数配置的**顶层**：

```js
// ❌ 错误：result 是 MonSQLize 构造函数的完整配置对象
result.useMemoryServer = true;
```

但 `connectMongo()` 实际从嵌套的 `config` 对象内部读取该字段：

```js
// connectMongo() 的实现
async function connectMongo({ databaseName, config, logger }) {
  let { uri, useMemoryServer } = config || {};  // 从 config 读，不是从顶层读
  // ...
}
```

调用链：`new MonSQLize(result)` → `this.config = options.config`（`result.config` = `mongoConfig`）→ `connectMongo({ config: this.config })` → `useMemoryServer` 永远为 `undefined`，内存服务器永不启动。

**修复方案**：

将 `useMemoryServer` 写入 `mongoConfig`（即 `result.config`）：

```ts
// ✅ 修复后：写入 mongoConfig（connectMongo 从中读取）
if (config.useMemoryServer) {
  mongoConfig.useMemoryServer = true;
}
```

**影响范围**：

- `src/lib/plugins/monsqlize/plugin.ts`（修复）
- `test/unit/plugins/monsqlize/plugin.test.ts`（更新断言：`passedConfig.config.useMemoryServer === true`）
- 所有配置了 `database.useMemoryServer: true` 的 vext 项目在无真实 MongoDB 环境下现在可正常启动

**发现背景**：此 Bug 在历史版本中被隐性规避（测试环境存在真实 MongoDB 实例，`uri` 生效，`useMemoryServer` 被忽略）。本次 vext-test 在无 MongoDB 实例的环境中验证时首次暴露。

## 🔄 升级指南

### 从 0.1.x 升级到 0.2.0

**无 Breaking Change**，直接升级即可：

```bash
npm install vextjs@0.2.0
```

**需注意的行为变更**：

1. **启动日志格式变更**（`host=0.0.0.0` 时）：
   - 旧：`[vextjs] ready on http://0.0.0.0:3000`
   - 新：多行展示 `Local + Network` 地址
   - 影响：如果你的部署脚本通过解析启动日志判断服务就绪（检测 `"ready on"` 字符串），需要同步更新检测逻辑为兼容 `" ready"` 或 `"[vextjs] ready"`

2. **`useMemoryServer` 修复**：
   - 此前版本中 `database.useMemoryServer: true` 在无真实 MongoDB 时不生效（静默失败，尝试连接 localhost:27017）
   - 0.2.0 起该配置生效，内存 MongoDB 实例将正常启动
   - 如果你的测试环境依赖外部 MongoDB 且同时配置了 `useMemoryServer: true`，框架将改为使用内存实例（测试隔离性更好）
