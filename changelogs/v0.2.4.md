## New Features

### F-01: `vext.preload` 自动注入

**背景**：

`vextjs-opentelemetry` 插件需要在应用启动前通过 `--import vextjs-opentelemetry/instrumentation` 初始化 SDK。此前用户必须手动配置启动命令：

```json
{
  "scripts": {
    "start": "node --import vextjs-opentelemetry/instrumentation ./dist/index.js"
  }
}
```

这给接入 OpenTelemetry（以及未来其他需要预加载的插件）带来了不必要的配置负担。

**变更内容**：

vext CLI 新增 preload 自动注入机制：

1. **`src/cli/utils/preload.ts`** — 新增 `resolvePreloads()` 工具函数
   - 扫描 `node_modules` 中所有已安装的 vext 插件
   - 读取每个插件 `package.json` 中的 `vext.preload` 字段
   - 返回需要以 `--import` 方式预加载的模块路径列表

2. **`src/cli/start.ts`** — `vext start` 命令自动注入 `--import` 参数

3. **`src/cli/dev.ts`** — `vext dev` 命令将 preload 列表传入 `ColdRestarter`

4. **`src/lib/dev/cold-restarter.ts`** — 新增 `extraExecArgv` 字段，子进程启动时自动追加 `--import` 参数

5. **`src/lib/bootstrap.ts`** — Cluster 多进程模式下，worker 进程同样自动透传 `execArgv`

**效果**：

安装 `vextjs-opentelemetry` 后，无需任何手动配置：

```bash
# 安装插件（含 vext.preload 字段）
npm install vextjs-opentelemetry @opentelemetry/api

# 直接启动 — 自动注入 --import vextjs-opentelemetry/instrumentation
vext start
vext dev
```

**兼容性**：

- 无 `vext.preload` 字段的插件完全不受影响（行为与之前一致）
- 已手动配置 `--import` 的项目不会重复注入（Node.js 会忽略重复的 `--import`）
