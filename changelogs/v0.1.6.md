## New Feature: Route-level Response Cache (Phase 1 MVP)

### CACHE-001: Declarative Route Cache

- **Design**: `plans/v1/15-route-cache.md`
- **16 files changed** (4 new + 12 modified)

Route-level response caching via declarative `RouteOptions.cache` configuration. Supports number shorthand (`cache: 60`) or full object configuration.

#### Usage

```typescript
// Number shorthand: cache for 60 seconds
app.get("/products", { cache: 60 }, async (req, res) => {
  res.json(await db.getProducts());
});

// Full configuration
app.get("/products", {
  cache: {
    ttl: 120,
    vary: ["accept-language"],
    tags: ["products"],
    condition: (req) => !req.query.refresh,
    cacheControl: true,
  },
}, async (req, res) => {
  res.json(await db.getProducts());
});

// Invalidate by tag (e.g. after product update)
app.post("/products", {}, async (req, res) => {
  await db.createProduct(req.body);
  await app.cache.invalidate("products");
  res.json({ created: true }, 201);
});
```

#### Features

| Feature | Description |
|---------|-------------|
| **LRU Memory Store** | Map-based LRU with configurable `maxEntries` (default 1000) |
| **TTL Expiry** | Per-route TTL in seconds, checked on read |
| **Vary Headers** | Different cache entries per Accept-Language, etc. |
| **Tag Invalidation** | `app.cache.invalidate(tag)` batch invalidation |
| **Conditional Caching** | `condition: (req) => boolean` to skip cache |
| **X-Cache Header** | `HIT` / `MISS` response header |
| **Cache-Control Header** | `public, max-age=N` with remaining TTL on HIT |
| **Auth Safety Warning** | Startup warning when auth + cache coexist without custom key |
| **`_onSend` Hook** | Captures pre-wrap data across all 5 adapters |
| **app.cache API** | `invalidate(tag)`, `delete(key)`, `clear()`, `stats()` |

## Bug Fixes

### BUG-023: `buildMonSQLizeConfig` type 字段映射错误

- **File**: `src/lib/plugins/monsqlize/plugin.ts`
- **Severity**: P1 (Critical — prevents connection)
- **Problem**: `type: config.type ?? "url"` passed to MonSQLize constructor, but MonSQLize only accepts `type: "mongodb"`. The vext `database.type` field (`url` / `replica` / `srv`) describes connection mode, not database type. Passing `"url"` caused `Invalid database type. Supported types are: mongodb` error.
- **Fix**: Hardcode `type: "mongodb"` in `buildMonSQLizeConfig()`. Connection mode is already encoded in the config structure (`url` vs `hosts` vs `host`), and MonSQLize auto-detects it.

### BUG-024: `buildMonSQLizeConfig` 的 `config.url` → `config.uri` 映射缺失

- **File**: `src/lib/plugins/monsqlize/plugin.ts`
- **Severity**: P1 (Critical — prevents connection)
- **Problem**: vext type definitions use `config.url` for the MongoDB connection string, but MonSQLize expects `config.uri`. The config was passed through without field name mapping, causing MonSQLize to throw `requires config.uri or config.useMemoryServer`.
- **Fix**: Added field name mapping in `buildMonSQLizeConfig()` — when `config.url` is present and `config.uri` is absent, automatically renames `url` → `uri`. The vext user-facing API (`config.url`) remains unchanged.

### BUG-025: `connection.ts` client getter 使用错误的属性路径

- **File**: `src/lib/plugins/monsqlize/connection.ts`
- **Severity**: P2 (Medium — breaks `db.client` access)
- **Problem**: Used `(monsqlize as any)._client` to access the underlying MongoClient, but MonSQLize stores it at `_adapter.client`.
- **Fix**: Changed to `(monsqlize as any)._adapter?.client` with proper null-safety and descriptive error message.

### BUG-026: model-loader 使用错误的 API 注册 Model

- **File**: `src/lib/plugins/monsqlize/model-loader.ts`
- **Severity**: P1 (Critical — model auto-loading broken)
- **Problem**: `loadLocalModels()` and `loadSharedModels()` called `monsqlize.model(name, definition)` to register models, but `monsqlize.model()` is a **getter** (single argument — collectionName) that retrieves an already-registered model. The second argument is silently ignored. Model registration requires the static method `Model.define(collectionName, definition)`.
- **Fix**: Refactored model-loader to dynamically import the `Model` class from monsqlize via `getModelClass()` helper, then call `Model.define(collectionName, definition)` for registration. Added `Model.has()` guard to prevent duplicate registration errors. Collection name resolution now prioritizes `definition.collection` > `definition.name` > filename-derived name.

### BUG-027: model-loader CJS/ESM interop 双层嵌套问题

- **File**: `src/lib/plugins/monsqlize/model-loader.ts`
- **Severity**: P1 (Critical — model auto-loading broken in built mode)
- **Problem**: When vext builds user code with esbuild (CJS format), model files output `module.exports = { __esModule: true, default: { name, schema, ... } }`. Node.js dynamic `import()` of CJS modules treats `module.exports` as the default export, resulting in `mod.default = { __esModule: true, default: { ... } }` (double nesting). The model-loader read `mod.default` and got the wrapper object (which lacks `schema`), not the actual definition.
- **Fix**: Added `__esModule` interop unwrapping: if `mod.default.__esModule` is truthy and `mod.default.default` exists, unwrap to `mod.default.default`.

## Refactoring

### Model Loader Architecture (`model-loader.ts`)

The model-loader was refactored to correctly use MonSQLize's API:

| Before (broken) | After (fixed) |
|---|---|
| `monsqlize.model(name, definition)` | `Model.define(collectionName, definition)` |
| Name from `definition.name` or filename | Collection name from `definition.collection` > `definition.name` > filename |
| No duplicate check | `Model.has(collectionName)` guard before define |
| No CJS/ESM interop | `__esModule` double-nesting unwrap |

New helper function `getModelClass()` dynamically imports MonSQLize to obtain the `Model` class with its static `define()` and `has()` methods.

## Migration Guide

No breaking changes for users. The fixes are internal to the MonSQLize plugin.

**If you were working around BUG-023/024** by manually setting `type: "mongodb"` or `config: { uri: "..." }` in your database config, you can now use the documented `config: { url: "..." }` format:

```typescript
// src/config/default.ts
export default {
  database: {
    config: {
      url: "mongodb://localhost:27017/mydb",  // ✅ Now correctly mapped to MonSQLize's `uri`
    },
    // type is no longer needed — always "mongodb" internally
  },
};
```

**Model definitions** in `src/models/` now work correctly with auto-loading:

```typescript
// src/models/user.ts
export default {
  name: "User",
  collection: "users",  // ← Used as the collectionName for Model.define()
  schema: {
    username: "string:3-32!",
    email: "email!",
    role: "admin|editor|viewer",
  },
};
```
