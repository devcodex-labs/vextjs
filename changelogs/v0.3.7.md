# v0.3.7 — 2026-05-21

## 概述

本版本聚焦 `vext dev` 开发链路的两个直接缺口收口：

1. `vext dev` 在首次启动、文件变更、手动 reload / restart、子进程请求 cold restart 前，统一执行开发期 preflight。
2. preflight 会先运行 typegen，再对 TypeScript 项目执行语义诊断；存在 blocking error 时不再继续热重载或重启。
3. reload 失败与子进程内异常现在会稳定输出完整错误堆栈，便于定位真实报错来源。
4. 脚手架不再预置静态 `src/types/services.d.ts`，改为转向 generated 类型产物链路，并让模板 `tsconfig.json` 显式纳入 `src/**/*.d.ts`。

---

## Added

- 新增 `src/cli/utils/dev-preflight.ts`，统一承接：
  - `runTypegen()`
  - TypeScript `getPreEmitDiagnostics()` 语义诊断
- `vext dev` 新增开发前置阻断能力：
  - initial start
  - file watcher cold restart / soft reload
  - manual cold restart / soft reload
  - child requested cold restart

---

## Changed

- `vext dev` 在进入新一轮重载前，先输出 typegen 产物写入与诊断结果。
- `src/types/generated/**` 现在会被 watcher 忽略，避免 typegen 写入 generated 声明后触发自激循环。
- TypeScript 脚手架模板 `tsconfig.json` 现在包含 `src/**/*.d.ts`，generated 声明可被默认项目自动纳入类型系统。

---

## Fixed

- 修复“TypeScript 源码存在错误时，`vext dev` 仍继续热重载/重启”的问题。
- 修复“reload 失败只打印 message、缺少 stack，难以定位真实异常”的问题。
- 修复“`services.generated.d.ts` 不会在开发链路自动生成”的问题。
- 修复“脚手架继续写静态 `src/types/services.d.ts`，与 generated 类型链路脱节”的问题。
