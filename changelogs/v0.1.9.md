# v0.1.9 - Adapter text() Content-Type 修复

**发布日期**: 2026-03-20
**版本类型**: Patch（Bug Fix）

---

## 摘要

修复所有 adapter（Hono / Express / Fastify / Koa / Native）中 `res.text()` 方法会强制覆盖用户通过 `res.setHeader("Content-Type", ...)` 预设的响应类型的问题。

---

## Bug Fixed

### BUG-031: `text()` 强制覆盖用户预设的 Content-Type

**影响版本**: v0.1.0 ~ v0.1.8
**修复版本**: v0.1.9
**严重程度**: 🔴 高（功能性 Bug，影响所有需要输出非 `text/plain` 文本响应的场景）

#### 问题描述

当用户通过 `res.setHeader("Content-Type", "text/html")` 预设响应类型，随后调用 `res.text(htmlContent)` 发送内容时，框架会将 Content-Type 强制覆盖为 `text/plain; charset=utf-8`，导致浏览器无法正确渲染 HTML。

典型失败场景：框架内置的 Scalar API 文档页面（`/docs` 路由），在浏览器中显示为 HTML 源码文本，而不是渲染后的交互式文档界面。

#### 根因

**Express / Fastify / Koa / Native（共同问题）**：`text()` 方法中 `applyHeaders()` 的调用顺序错误。

```typescript
// ❌ 修复前（错误顺序）
applyHeaders(); // 先应用用户设置
expressRes.setHeader("Content-Type", "text/plain; ..."); // 再设默认值 → 覆盖了用户设置

// ✅ 修复后（正确顺序）
expressRes.setHeader("Content-Type", "text/plain; ..."); // 先设默认值
applyHeaders(); // 再应用用户设置 → 用户设置可覆盖默认值
```

**Hono（独立问题）**：`text()` 方法调用了 `c.text(content)`，Hono 内部会在创建 Response 时强制重写 `Content-Type: text/plain`，无视已通过 `c.header()` 设置的值。

```typescript
// ❌ 修复前
captureResponse(c.text(content)); // c.text() 内部强制重写 Content-Type

// ✅ 修复后
captureResponse(c.body(content)); // c.body() 不干预 Content-Type，完全尊重已设置的头信息
```

#### 修复文件

| 文件                               | 修复内容                                                                          |
| ---------------------------------- | --------------------------------------------------------------------------------- |
| `src/adapters/express/response.ts` | `text()` 方法调整 `applyHeaders()` 调用位置（在设默认值之后）                     |
| `src/adapters/fastify/response.ts` | 同上                                                                              |
| `src/adapters/koa/response.ts`     | 同上                                                                              |
| `src/adapters/native/response.ts`  | 同上                                                                              |
| `src/adapters/hono/response.ts`    | `text()` 方法将 `c.text()` 替换为 `c.body()`，避免 Hono 内部强制重写 Content-Type |

#### 行为变更对照

| 调用方式                                                        | v0.1.8 行为            | v0.1.9 行为                     |
| --------------------------------------------------------------- | ---------------------- | ------------------------------- |
| `res.text(content)`                                             | `text/plain` ✅        | `text/plain` ✅（无变化）       |
| `res.setHeader("Content-Type", "text/html")` + `res.text(html)` | `text/plain` ❌（Bug） | `text/html` ✅（修复）          |
| `res.setHeader("Content-Type", "text/csv")` + `res.text(csv)`   | `text/plain` ❌（Bug） | `text/csv` ✅（修复）           |
| `res.json(data)`                                                | `application/json` ✅  | `application/json` ✅（无变化） |

#### Breaking Changes

**无**。本次修复不引入 Breaking Change：

- 单独调用 `res.text()` 的行为完全不变（仍为 `text/plain`）
- 仅修复了 `setHeader` + `text()` 组合使用时的异常行为（旧行为是 Bug，不应被依赖）

## Upgrade Guide

### From v0.1.8

直接升级，无需任何代码变更：

```json
"vextjs": "^0.1.9"
```

如果你的项目中有以下模式的代码，升级后行为将**自动修正**（无需改动）：

```typescript
// 这段代码在 v0.1.8 中 Content-Type 会被错误地设为 text/plain
// 升级到 v0.1.9 后将正确输出 text/html
res.setHeader("Content-Type", "text/html; charset=utf-8");
res.text(htmlContent);
```
